Soporte técnico por conocimiento · Octubre de 2026

Diagnosticar y resolver conflictos de acceso a Windows de forma remota y autorizada.

Un runbook reproducible, escrito en lenguaje natural y con ejemplos de PowerShell. Incluye un mapa exhaustivo de los 250 recursos de Nexus: cada ficha indica una acción y enlaza a su fuente, incluso cuando su utilidad para el incidente es indirecta o nula.

Alcance y autorización

El técnico debe tener solicitud identificable, consentimiento del usuario o autorización organizacional, cuenta propia con permisos aprobados y un canal seguro. Esta guía no enseña a eludir contraseñas, MFA, UAC, BitLocker, EDR, controles de dominio ni consentimiento de escritorio remoto. Herramientas ofensivas se incluyen como conocimiento defensivo, nunca como método de acceso. Los datos de los ejemplos son ficticios y ninguna reparación se ha ejecutado en un Windows real.

1. Flujo de soporte: de incidencia a cierre

Ticket + autorizaciónClasificar bloqueoCanal consentidoDiagnóstico no destructivoCorrección oficialRevalidarRegistrar evidenciaCerrar o escalar
Paso 1 · Triage

Qué conflicto existe

Preguntar al usuario si Windows permite iniciar sesión local, si falla RDP, si existe un error de contraseña/MFA o si el equipo está desconectado. Registrar edición Windows, mensaje exacto, hora, hostname, VPN y cambios recientes. Si no hay sesión local, no prometer asistencia desatendida.

Paso 2 · Canal seguro

Asistencia rápida

Si el usuario ya inició sesión, abrir Asistencia rápida (Ctrl + Windows + Q), confirmar identidad por canal conocido, compartir el código temporal y solicitar permiso de visualización o control. Si la sesión ni siquiera abre, utilizar canales TI oficialmente habilitados o asistencia presencial; nunca pedir contraseñas al usuario.

Paso 3 · Red y servicio

Diagnóstico de RDP

Con permiso para administrar el host: confirmar resolución DNS, ruta VPN y disponibilidad TCP de RDP. Un puerto abierto solo demuestra conectividad, no que la autenticación vaya a funcionar.

Paso 4 · Identidad y política

Cuenta y permisos

Distinguir usuario inexistente, bloqueo, contraseña expirada, credenciales incorrectas, MFA, NLA, pertenencia a grupo de acceso remoto y restricciones de inicio de sesión. Solicitar al equipo responsable el restablecimiento o corrección mediante el procedimiento oficial.

Paso 5 · Corrección aprobada

Menor cambio posible

Aplicar una sola corrección revisable: DNS/VPN, servicio RDP, membresía aprobada, política de host o autenticación regular. Antes: evidencia y punto de retorno. Después: comprobar acceso y no ampliar la exposición a Internet.

Paso 6 · Evidencia y cierre

Verificación reproducible

Repetir la prueba con cuenta autorizada, registrar evento y hora sin guardar secretos, confirmar cierre con el usuario y documentar causa raíz, responsables y plan preventivo.

2. Ejemplos de diagnóstico seguro (PowerShell)

Ejecute desde el equipo de soporte, sin necesidad de privilegios sobre el host remoto. Sustituya el hostname por el del activo autorizado:

$Equipo = "PC-SOPORTE-023" # Ejemplo ficticio
Resolve-DnsName -Name $Equipo -ErrorAction Continue
Test-NetConnection -ComputerName $Equipo -Port 3389 -InformationLevel Detailed
# Si usa VPN corporativa, verificar primero su conexión.
# No interpretar TcpTestSucceeded como autenticación correcta.

Si el usuario autorizó una sesión y el técnico dispone de permisos, pedirle ejecutar localmente estos comandos de solo lectura mediante Asistencia rápida:

whoami
whoami /groups
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber
Get-Service -Name TermService | Select-Object Name, Status, StartType
Get-NetFirewallRule -DisplayGroup "Remote Desktop" -ErrorAction SilentlyContinue |
 Select-Object DisplayName, Enabled, Profile, Direction, Action
# El grupo de reglas puede llamarse diferente según idioma o versión.

3. Si hay errores de identidad, autenticación o sesión

En el equipo afectado, bajo consentimiento y según política interna:

whoami /upn
# Solo en equipos unidos a Entra ID o híbridos:
dsregcmd /status
# Revisar eventos recientes SIN exportar contraseñas ni secretos:
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-2)} -MaxEvents 10 |
 Select-Object TimeCreated, Id, ProviderName, Message

La lectura del registro de seguridad puede requerir elevación. Los eventos 4625 ayudan a investigar intentos fallidos, pero algunos fallos de RDP se registran además en registros TerminalServices. El diagnóstico de cuentas debe considerar Active Directory/Entra y las políticas reales.

Qué NO hacer

No desactivar Defender, antivirus, firewall o MFA para “probar”. No modificar credenciales en memoria, instalar proveedores de credenciales ajenos, exponer RDP/3389 a Internet ni utilizar herramientas del catálogo para capturar passwords. Si RDP está bloqueado por política, solicitar la excepción aprobada o usar el canal de soporte institucional.

[pscustomobject]@{

} | ConvertTo-Json
# Éxito real: prueba de inicio de sesión aprobada + confirmación del usuario.
# Guardar resultados sin contraseñas, tokens ni PII innecesaria.
  • Resuelto: identidad verificada, camino de red permitido, acceso restaurado bajo las políticas vigentes y validado con el usuario.
  • No resuelto: persistencia de error 4625, denegación por políticas, host apagado, firewall central o falta de permisos: escalar a administrador de dominio, red o puesto de trabajo con evidencia.
  • Sin contacto local: Quick Assist no puede resolver por sí misma una pantalla de login inaccesible; activar canal empresarial con autorización o visita física.

5. Seguridad, análisis de riesgos y límites

Los repositorios de análisis de credenciales, pentesting, simulación adversaria, pruebas de controles, observabilidad y evaluación de agentes permiten comprender amenazas y reforzar políticas. Su relación con esta incidencia es investigación y hardening, no obtención de acceso. Documente hallazgos y pruebe cualquier PoC solo en laboratorio propio y autorizado.

6. Automatizar tickets sin perder trabajo

Con DBOS/PostgreSQL (guía técnica 01), un workflow puede registrar diagnóstico, aprobaciones, resultado de cada paso y reintentos de consultas remotas. El restablecimiento de accesos debe exigir verificación de identidad y aprobación humana; no automatice cambios de cuentas por una respuesta generada por IA.

# Ejemplo: consulta de diagnóstico solo lectura, con salida estructurada
$Estado = [pscustomobject]@{
 Host = "PC-SOPORTE-023"
 Puerto3389 = Test-NetConnection -ComputerName "PC-SOPORTE-023" -Port 3389 -InformationLevel Quiet
 ComprobadoUTC = (Get-Date).ToUniversalTime().ToString("o")
}
$Estado | ConvertTo-Json -Depth 3
# Persistir JSON como evidencia del ticket con permisos y retención definidos.
