Reference Architecture MCP · 2026

Cómo fluye una conexión MCP

Un host de IA crea un cliente MCP que se comunica con un servidor mediante un transporte. El servidor expone capacidades controladas —como tools, resources y prompts— hacia sistemas y datos concretos.

01

Host / Agente

Aplicación de IA que decide cuándo necesita contexto o una acción externa.

02

MCP Client

Mantiene la conexión lógica y envía solicitudes al servidor MCP autorizado.

03

Streamable HTTP

Transporte recomendado para un servidor MCP remoto. La autorización se aplica en este límite de confianza.

04

MCP Server

Expone únicamente las capacidades que el host puede descubrir y utilizar.

Tools

Acciones ejecutables con esquema de entrada definido y validación del servidor.

Resources

Datos y contenido que el servidor hace accesibles mediante interfaces MCP.

Prompts

Plantillas y flujos de interacción expuestos por el servidor cuando aplica.

Límites de confianza

REMOTE BOUNDARY
Autorización
OAuth / credenciales verificadas para servidores remotos.
Mínimo privilegio
Expón solo tools y datos necesarios para el caso de uso.
Validación
Valida argumentos, identidad, origen y límites antes de ejecutar.
Auditoría
Registra llamadas sensibles sin volcar secretos ni tokens en logs.

Arquitectura de referencia: adapta autenticación, aislamiento y permisos al riesgo real de cada servidor.
